These examples use the one-shot commands, which print and exit. They follow the demo organization, Acme Payments, where `payments-api` and `orders-api` run in `prod-us-east-1`.

## Start the day

```bash
rubix status
```

You get the open critical and high incidents, what needs you, the Tasks waiting and your environments. Then pick up your own work:

```bash
rubix tasks owner:me
```

## Ask about something in front of you

Pipe logs, a diff or a manifest straight to Rubix:

```bash
kubectl logs deploy/payments-api -n payments --since=15m | rubix -p "why is this crash-looping?"
```

```bash
git diff main -- deploy/orders-api.yaml | rubix -p "what could go wrong if I roll this out?" --env prod-us-east-1
```

The CLI prints `rubix chat -s <id>` after the answer. Run it to carry on in chat.

## Look at one incident

```bash
rubix incidents sev:high env:prod
rubix incident INC-12
```

`rubix incident` shows what was detected, the RCA, the Tasks and the activity. To act on it, open it in Browse with `rubix browse INC-12`.

## Make an alias

```bash
alias what-changed='rubix -p "What changed in prod-us-east-1 in the last hour, and is any of it related to open incidents?"'
```

## Use JSON in your own scripts

Every list and record takes `--json`. Pick out what you need with `jq`:

```bash
rubix incidents sev:critical --json | jq -r '.items[] | .code + "  " + .title'
```

A list prints `{ "total": …, "items": [ … ] }`, and each item has its `code`, `title`, `state` and `facts`. A record prints its fields, its link and its sections.

```bash
rubix -p "Summarise today's incidents in five lines." --json | jq -r .answer > summary.md
```

Check the exit code in case Rubix stops for you. `rubix -p` exits with 2 when Rubix needs an approval or asked a question, and prints the chat to open.

```bash
rubix -p "Restart the payments-api pods that are crash-looping." --json > answer.json
if [ $? -eq 2 ]; then
  echo "Rubix is waiting for you: $(jq -r .waiting answer.json)"
fi
```

<Note>
  The CLI signs in as you, so every command runs with your access and is recorded under your name. Run it where you'd sign in yourself, not on a shared machine.
</Note>
