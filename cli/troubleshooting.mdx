## Install

<AccordionGroup>
  <Accordion title="npm says the engine is unsupported, or the CLI won't start">
    The CLI needs Node.js 22.12 or newer. Check with `node --version`. With nvm, run `nvm install 22` and `nvm use 22`, then install the CLI again. With Homebrew, run `brew upgrade node`.
  </Accordion>
  <Accordion title="rubix: command not found">
    npm's global `bin` folder isn't on your `PATH`. Run `npm prefix -g` and add the `bin` folder inside it to your `PATH` in your shell profile. With nvm or asdf, install the CLI again after you switch Node versions, because each version has its own global packages.
  </Accordion>
  <Accordion title="The version is older than expected">
    Run `npm install -g @rubixkube/rubix@latest`. With npx, run `npx @rubixkube/rubix@latest` once to skip a cached copy.
  </Accordion>
</AccordionGroup>

## Sign in

<AccordionGroup>
  <Accordion title="The browser doesn't open">
    Copy the link the CLI prints into any browser, on any device, and enter the code. This is the usual way over SSH.
  </Accordion>
  <Accordion title="The code expired">
    Run `rubix login` again for a new code, and approve it straight away. Codes expire.
  </Accordion>
  <Accordion title="Not signed in. Run `rubix login` first.">
    Your sign-in is missing or has ended. Run `rubix login`. If it keeps happening, run `rubix logout` and then `rubix login` for a clean start.
  </Accordion>
  <Accordion title="I'm in the wrong organization">
    The CLI uses your account's home organization, the one you signed up to or were first invited to. It doesn't switch between organizations. Use the console to work in another one.
  </Accordion>
</AccordionGroup>

## Chat

<AccordionGroup>
  <Accordion title="Rubix won't make a change">
    The mode decides what Rubix can do. In Observe, nothing that changes anything runs. Switch with `/mode` or Shift+Tab, up to your organization's highest mode. See [Modes](/using/modes).
  </Accordion>
  <Accordion title="rubix -p exits with code 2">
    Rubix needs an approval or asked a question. Run the `rubix chat -s <id>` line it printed and answer there.
  </Accordion>
  <Accordion title="Rubix looks at the wrong environment">
    Pick one with `/env <name>`, or pass `--env <name>` to `rubix -p`. `/env` on its own lists the names.
  </Accordion>
  <Accordion title="A file I named with @ wasn't sent">
    Text files go in up to 256 KB, and images and PDFs up to 20 MB. Check the path is relative to the folder you started `rubix` in, such as `@./logs/app.log`.
  </Accordion>
  <Accordion title="Ctrl+G says it couldn't open an editor">
    Set `VISUAL` or `EDITOR` to your editor, such as `export EDITOR=nano`.
  </Accordion>
</AccordionGroup>

## The terminal

<AccordionGroup>
  <Accordion title="Long pastes get cut off">
    Some terminals cut long pastes. Use `/paste` to read from the clipboard, or Ctrl+G to write in your editor.
  </Accordion>
  <Accordion title="Mouse clicks do odd things, or I can't select text">
    In Browse, dragging selects and copies. Shift-drag uses your terminal's own selection. Set `RUBIX_MOUSE=0` to turn the mouse off.
  </Accordion>
  <Accordion title="Links show as raw text, or don't open">
    Set `RUBIX_LINKS=1` to turn terminal hyperlinks on, or `RUBIX_LINKS=0` to turn them off.
  </Accordion>
  <Accordion title="The pixel Rubix or colours look wrong">
    Set `RUBIX_MASCOT=0` for plain text, or `NO_COLOR=1` for no colour at all.
  </Accordion>
</AccordionGroup>

## Network

The CLI needs HTTPS access to three hosts: `console.rubixkube.ai` for everything it does, `rubixkube.us.auth0.com` to sign in, and `registry.npmjs.org` for the daily update check. It connects to them directly, so allow them on your firewall or VPN.
