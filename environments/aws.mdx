---
title: "AWS"
description: "Connect an AWS account by running the observer on a machine you have, or on a new EC2 instance."
---

Connect an AWS account and the observer maps what's in it, then watches its metrics and CloudTrail. It reads through the AWS API, so you run one observer for the account.

You pick where it runs:

- **On this machine.** The observer runs as a Docker container named `rk-observer` on a Linux host you already have. It reads with an access key from an IAM user you create.
- **A new EC2 instance.** The installer creates a `t3.micro` instance, the IAM role and policy. The observer runs there as a systemd service named `rk-observer`, and no AWS keys are stored.


## Install

In the console, open **Environments**, click **Connect** and pick **Amazon AWS**. Copy the key from step 2 of the dialog. Then follow one path.

<Tabs>
  <Tab title="On this machine">
    You need a Linux host with outbound access to `api.rubixkube.ai:443`, `nats.rubixkube.ai:4222`, `ghcr.io:443` and the AWS APIs. The installer installs Docker if it's missing, on systems with `apt-get`, `dnf` or `yum`.

    <Steps>
      <Step title="Create an IAM user">
        Create a user, such as `rubixkube-observer`, and give it an access key. For its permissions, use the policy under [IAM permissions](#iam-permissions), or the `ReadOnlyAccess` managed policy. The installer can print the policy as JSON.
      </Step>
      <Step title="Run the installer as root">
        ```bash
        curl -fsSL "https://api.rubixkube.ai/install/observer.sh" | sudo bash
        ```

        The dialog shows the command without `sudo`. Add it unless you're already root.
      </Step>
      <Step title="Answer the questions">
        Paste your RubixKube key, then:

        ```
        What would you like to do?
          1) Install Observer
          2) Uninstall Observer
        > 1

        Where do you want to deploy the observer?
          1) On this machine
          2) Create a new AWS EC2 instance
          3) Create a new GCP Compute Engine instance
          4) Create a new Azure Virtual Machine
        > 1

        Which platform are you monitoring?
          1) VM / host (Linux or macOS)
          2) AWS
          3) GCP
          4) Azure
        > 2

        AWS Region [us-east-1]:
        ```

        Then paste the access key ID and secret access key, and pick the regions to watch: this region only, all enabled regions, or a list. The keys are saved in `/etc/rk-observer/observer.env`, which only root can read.
      </Step>
      <Step title="Check the container">
        ```bash
        sudo docker ps --filter name=rk-observer
        sudo docker logs -f rk-observer
        ```
      </Step>
    </Steps>
  </Tab>
  <Tab title="A new EC2 instance">
    You need the AWS CLI on your machine. `aws sts get-caller-identity` must work, with permission to create IAM policies, roles and instance profiles, and to launch an instance.

    <Note>
      The instance is in your account, so AWS bills you for it. The installer doesn't pick a subnet, so the region needs a default VPC.
    </Note>

    <Steps>
      <Step title="Run the installer">
        Don't use `sudo` here. The installer needs your own AWS sign-in.

        ```bash
        curl -fsSL "https://api.rubixkube.ai/install/observer.sh" | bash
        ```
      </Step>
      <Step title="Answer the questions">
        Paste your RubixKube key, then:

        ```
        What would you like to do?
          1) Install Observer
          2) Uninstall Observer
        > 1

        Where do you want to deploy the observer?
          1) On this machine
          2) Create a new AWS EC2 instance
          3) Create a new GCP Compute Engine instance
          4) Create a new Azure Virtual Machine
        > 2

        AWS Region [us-east-1]:
        ```

        Then pick the regions to watch: this region only, all enabled regions, or a list.
      </Step>
      <Step title="See what it created">
        - IAM policy `RubixKubeObserverPolicy`
        - IAM role `RubixKubeObserverRole`
        - Instance profile `RubixKubeObserverProfile`
        - A `t3.micro` instance on Amazon Linux 2023, named `rk-observer-` plus the date and time, tagged `rubixkube=observer`
      </Step>
      <Step title="Check the instance">
        It connects once the instance boots, in about two minutes.

        ```bash
        aws ec2 describe-instances \
          --region us-east-1 \
          --filters "Name=tag:rubixkube,Values=observer" \
          --query 'Reservations[].Instances[].{ID:InstanceId,Status:State.Name,Name:Tags[?Key==`Name`]|[0].Value}'
        ```

        To look for errors during boot:

        ```bash
        aws ec2 get-console-output --region us-east-1 --instance-id i-0abc123 --query 'Output' --output text | grep -i error
        ```
      </Step>
    </Steps>
  </Tab>
</Tabs>

When the observer reports in, the dialog says the account is connected. Add an environment label, then click **Open it**.

## What the observer watches

| Service | What |
|---|---|
| EC2 and EBS | Instances and volumes |
| VPC | Networks, subnets, security groups, route tables |
| RDS | Database instances and clusters |
| S3 | Buckets |
| Lambda | Functions |
| ELB | Load balancers |
| EKS | Clusters. For what's inside one, [install the Kubernetes observer](/environments/kubernetes) too |
| IAM | Roles |
| CloudWatch | Metrics, alarms and logs |
| CloudTrail | Changes in the account |

It refreshes the inventory every 10 minutes, metrics every 2 minutes and CloudTrail every 5 minutes.

## IAM permissions

These are the read permissions the observer uses, with `Resource: "*"`:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "RubixKubeObserverReadOnly",
      "Effect": "Allow",
      "Action": [
        "ec2:DescribeInstances",
        "ec2:DescribeVpcs",
        "ec2:DescribeSubnets",
        "ec2:DescribeSecurityGroups",
        "ec2:DescribeRouteTables",
        "ec2:DescribeNetworkAcls",
        "ec2:DescribeVolumes",
        "ec2:DescribeRegions",
        "elasticloadbalancing:DescribeLoadBalancers",
        "rds:DescribeDBInstances",
        "rds:DescribeDBClusters",
        "rds:ListTagsForResource",
        "s3:ListAllMyBuckets",
        "s3:GetBucketLocation",
        "s3:GetBucketPolicyStatus",
        "iam:ListRoles",
        "eks:ListClusters",
        "eks:DescribeCluster",
        "lambda:ListFunctions",
        "lambda:GetFunctionConfiguration",
        "cloudwatch:DescribeAlarms",
        "cloudwatch:GetMetricData",
        "cloudwatch:GetMetricStatistics",
        "cloudwatch:ListMetrics",
        "logs:FilterLogEvents",
        "logs:GetLogEvents",
        "logs:DescribeLogGroups",
        "logs:DescribeLogStreams",
        "cloudtrail:LookupEvents",
        "sts:GetCallerIdentity"
      ],
      "Resource": "*"
    }
  ]
}
```

On a new EC2 instance, `RubixKubeObserverPolicy` also allows `aws-mcp:*`, so the observer can use the AWS MCP server. `logs:FilterLogEvents` and `logs:GetLogEvents` read the contents of CloudWatch logs, so check that fits your rules.

## More than one account

Connect each account as its own source. Rubix can read across all of them, and you can put them under one [environment label](/using/environments#label-a-source).

## Troubleshooting

<AccordionGroup>
  <Accordion title="The container isn't running">
    ```bash
    sudo docker logs rk-observer --tail 50
    ```

    Check the API key and AWS keys in `/etc/rk-observer/observer.env`, and that outbound `api.rubixkube.ai:443` and `nats.rubixkube.ai:4222` are open.
  </Accordion>
  <Accordion title="The installer can't pull the image">
    The host can't reach `ghcr.io`. The image is `ghcr.io/rubixkube-io/observer-agent:aws-latest`. Allow outbound HTTPS to `ghcr.io` and run the installer again.
  </Accordion>
  <Accordion title="Permission errors">
    Compare the IAM user or role with the policy above. On a new instance, check that `RubixKubeObserverRole` still has `RubixKubeObserverPolicy` attached.
  </Accordion>
  <Accordion title="Timeouts to AWS APIs">
    A host in a VPC with no NAT gateway or VPC endpoints can't reach the AWS APIs. Add them, or run the observer on a host with public egress.
  </Accordion>
</AccordionGroup>

## Uninstall

Run the installer with `--uninstall`, so it doesn't ask for a key. Which steps you follow depends on where the observer runs.

**On this machine:**

```bash
curl -fsSL "https://api.rubixkube.ai/install/observer.sh" | sudo bash -s -- --uninstall
```

Pick **1) This machine (local install)**, then **2) GCP / Azure (Docker)**. The second label doesn't say AWS, but the AWS observer on a machine runs in Docker, so this is the right one. It removes the container and `/etc/rk-observer`. Then delete the IAM user yourself.

**On a new EC2 instance:**

```bash
curl -fsSL "https://api.rubixkube.ai/install/observer.sh" | bash -s -- --uninstall
```

Pick **2) AWS EC2 instance + IAM resources**, then enter the region and choose the instances.

<Warning>
  This permanently terminates the instances you pick, after you type `yes`. If you pick every instance in the region, it also deletes `RubixKubeObserverRole`, `RubixKubeObserverPolicy` and `RubixKubeObserverProfile`. Don't do that while observers run in another region, because they share those three. If you pick only some instances, the IAM resources stay.
</Warning>

Then delete the source in the console.
