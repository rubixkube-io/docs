---
title: "Google Cloud"
description: "Connect a Google Cloud project by running the observer on a machine you have, or on a new Compute Engine instance."
---

Connect a Google Cloud project and the observer maps what's in it, then watches its metrics and logs. It reads through the Google Cloud APIs, so you run one observer for the project.

You pick where it runs. Either way, the observer is a Docker container.

- **On this machine.** It runs as a container named `rk-observer` on a Linux host you already have, and reads with the Google Cloud credentials on that host.
- **A new Compute Engine instance.** The installer creates an `e2-micro` instance, a service account and the network it needs.


## Install

In the console, open **Environments**, click **Connect** and pick **Google Cloud**. Copy the key from step 2 of the dialog. Then follow one path.

<Tabs>
  <Tab title="On this machine">
    You need a Linux host with outbound access to `api.rubixkube.ai:443`, `nats.rubixkube.ai:4222`, `ghcr.io:443` and the Google APIs. The installer installs Docker if it's missing, on systems with `apt-get`, `dnf` or `yum`.

    This path doesn't create a service account or enable any APIs. Enable the APIs under [Permissions](#permissions), and give the credentials the roles listed there.

    <Steps>
      <Step title="Sign in as root">
        The installer runs as root and mounts root's `~/.config/gcloud` into the container.

        ```bash
        sudo gcloud auth application-default login
        ```
      </Step>
      <Step title="Run the installer as root">
        ```bash
        curl -fsSL "https://api.rubixkube.ai/install/observer.sh" | sudo bash
        ```

        The dialog shows the command without `sudo`. Add it unless you're already root.
      </Step>
      <Step title="Answer the questions">
        Paste your RubixKube key, then:

        ```
        What would you like to do?
          1) Install Observer
          2) Uninstall Observer
        > 1

        Where do you want to deploy the observer?
          1) On this machine
          2) Create a new AWS EC2 instance
          3) Create a new GCP Compute Engine instance
          4) Create a new Azure Virtual Machine
        > 1

        Which platform are you monitoring?
          1) VM / host (Linux or macOS)
          2) AWS
          3) GCP
          4) Azure
        > 3

        GCP Project ID:
        ```
      </Step>
      <Step title="Check the container">
        ```bash
        sudo docker ps --filter name=rk-observer
        sudo docker logs -f rk-observer
        ```
      </Step>
    </Steps>
  </Tab>
  <Tab title="A new Compute Engine instance">
    You need `gcloud` on your machine, signed in with permission to enable APIs, create service accounts and custom roles, change IAM bindings, and create network resources and instances. The project needs the `default` network.

    <Note>
      Everything it creates is in your project, so Google bills you for it. That includes Cloud NAT.
    </Note>

    <Steps>
      <Step title="Run the installer">
        Don't use `sudo` here. The installer needs your own `gcloud` sign-in.

        ```bash
        curl -fsSL "https://api.rubixkube.ai/install/observer.sh" | bash
        ```
      </Step>
      <Step title="Answer the questions">
        Paste your RubixKube key, then:

        ```
        What would you like to do?
          1) Install Observer
          2) Uninstall Observer
        > 1

        Where do you want to deploy the observer?
          1) On this machine
          2) Create a new AWS EC2 instance
          3) Create a new GCP Compute Engine instance
          4) Create a new Azure Virtual Machine
        > 3

        GCP Project ID [your-project]:
        Region [us-central1]:
        ```
      </Step>
      <Step title="See what it created">
        - Service account `rk-observer`, with the roles under [Permissions](#permissions)
        - Custom role `RKObserverStorageViewer`
        - Cloud Router `rk-observer-router` and Cloud NAT `rk-observer-nat`, because the instance has no public IP
        - Egress firewall rules `rk-observer-allow-nats` (TCP 4222) and `rk-observer-allow-https` (TCP 443)
        - An `e2-micro` instance on Container-Optimized OS in zone `<region>-a`, named `rk-observer-` plus the date, labelled `rubixkube=observer`
      </Step>
      <Step title="Check the instance">
        It connects in about a minute.

        ```bash
        gcloud compute instances list --filter="labels.rubixkube=observer"
        ```

        To look for errors during boot:

        ```bash
        gcloud compute instances get-serial-port-output INSTANCE_NAME --zone=us-central1-a
        ```
      </Step>
    </Steps>
  </Tab>
</Tabs>

When the observer reports in, the dialog says the project is connected. Add an environment label, then click **Open it**.

## What the observer watches

| Service | What |
|---|---|
| Compute Engine | Instances, networks and forwarding rules |
| GKE | Clusters. For what's inside one, [install the Kubernetes observer](/environments/kubernetes) too |
| Cloud SQL | Instances |
| Cloud Run | Services |
| Cloud Functions | Functions |
| Cloud Storage | Buckets |
| Pub/Sub | Topics |
| Cloud Monitoring | Metrics |
| Cloud Logging | Error logs |

It refreshes the inventory every 10 minutes, metrics every 2 minutes and logs every 5 minutes.

## Permissions

The observer needs these roles on the project. A new instance gets them on its service account:

- `roles/compute.viewer`
- `roles/monitoring.viewer`
- `roles/logging.viewer`
- `roles/cloudsql.viewer`
- `roles/run.viewer`
- `roles/cloudfunctions.viewer`
- `roles/container.viewer`
- `roles/pubsub.viewer`
- `RKObserverStorageViewer`, a custom role with `storage.buckets.get` and `storage.buckets.list`

`roles/logging.viewer` lets it read log contents, so check that fits your rules.

These are the APIs the new-instance path enables. Run this yourself if you install on your own machine:

```bash
gcloud services enable compute.googleapis.com monitoring.googleapis.com \
  logging.googleapis.com storage.googleapis.com sqladmin.googleapis.com \
  run.googleapis.com cloudfunctions.googleapis.com container.googleapis.com \
  pubsub.googleapis.com cloudresourcemanager.googleapis.com
```

## More than one project

Connect each project as its own source. Rubix can read across all of them, and you can put them under one [environment label](/using/environments#label-a-source).

## Troubleshooting

<AccordionGroup>
  <Accordion title="The container isn't running">
    ```bash
    sudo docker logs rk-observer --tail 50
    ```

    Check the API key in `/etc/rk-observer/observer.env`, and that outbound `api.rubixkube.ai:443` and `nats.rubixkube.ai:4222` are open.
  </Accordion>
  <Accordion title="The installer warned about gcloud credentials">
    It found nothing at `~/.config/gcloud`, so the container has nothing to sign in with. Run `sudo gcloud auth application-default login`, then run the installer again.
  </Accordion>
  <Accordion title="The installer can't pull the image">
    The host can't reach `ghcr.io`. The image is `ghcr.io/rubixkube-io/observer-agent:gcp-latest`. Allow outbound HTTPS to `ghcr.io` and run the installer again.
  </Accordion>
  <Accordion title="Permission errors">
    Check what the service account has:

    ```bash
    gcloud projects get-iam-policy PROJECT_ID --flatten='bindings[].members' --filter='bindings.members:rk-observer@PROJECT_ID.iam.gserviceaccount.com'
    ```

    Add anything missing from [Permissions](#permissions).
  </Accordion>
</AccordionGroup>

## Uninstall

Run the installer with `--uninstall`, so it doesn't ask for a key. Which steps you follow depends on where the observer runs.

**On this machine:**

```bash
curl -fsSL "https://api.rubixkube.ai/install/observer.sh" | sudo bash -s -- --uninstall
```

Pick **1) This machine (local install)**, then **2) GCP / Azure (Docker)**. It removes the container and `/etc/rk-observer`.

**On a new Compute Engine instance:**

```bash
curl -fsSL "https://api.rubixkube.ai/install/observer.sh" | bash -s -- --uninstall
```

Pick **3) GCP Compute Engine instance + IAM + network resources**, enter the project and region, then choose the instances.

<Warning>
  This permanently deletes the instances you pick, after you type `yes`. If you pick every instance, it also deletes the firewall rules, Cloud NAT, Cloud Router, the role bindings, the service account and the custom role. If you pick only some instances, those stay.
</Warning>

Then delete the source in the console.
