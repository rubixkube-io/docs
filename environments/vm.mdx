Use this for machines that live outside your cloud accounts: bare metal, a one-off VM, a build server. The installer puts a small binary on the machine and runs it as a service.

## Before you start

- **Linux with systemd**, or **macOS**. On x86_64 or arm64. The installer stops on Linux without systemd, so Alpine doesn't work. Windows isn't supported yet.
- `curl`, `bash`, and root or `sudo`.
- Outbound access to `api.rubixkube.ai:443`, `nats.rubixkube.ai:4222`, and `github.com:443` for the download.
- An admin account in the [console](https://console.rubixkube.ai).

## Install

<Steps>
  <Step title="Get your key">
    In the console, open **Environments**, click **Connect** and pick **Servers and VMs**. Copy the key from step 2 of the dialog.
  </Step>
  <Step title="Run the installer on the machine">
    ```bash
    curl -fsSL "https://api.rubixkube.ai/install/observer.sh" | sudo bash
    ```

    The dialog shows the command without `sudo`. Add it unless you're already root, because this install needs root.
  </Step>
  <Step title="Paste the key and answer the questions">
    ```
    RubixKube API Key: rk_...

    What would you like to do?
      1) Install Observer
      2) Uninstall Observer
    > 1

    Where do you want to deploy the observer?
      1) On this machine
      2) Create a new AWS EC2 instance
      3) Create a new GCP Compute Engine instance
      4) Create a new Azure Virtual Machine
    > 1

    Which platform are you monitoring?
      1) VM / host (Linux or macOS)
      2) AWS
      3) GCP
      4) Azure
    > 1
    ```
  </Step>
  <Step title="Open it in the console">
    The dialog updates by itself and says your machine is connected, usually within a minute. Add an environment label, then click **Open it**.
  </Step>
</Steps>

The installer puts the binary at `/usr/local/bin/rk-observer` and its settings in `/etc/rk-observer/observer.env`. That file holds your API key and only root can read it. The machine's short hostname becomes the source's name.

## Check the service

<Tabs>
  <Tab title="Linux">
    The service is called `rk-observer`.

    ```bash
    sudo systemctl status rk-observer
    sudo journalctl -u rk-observer -f
    ```
  </Tab>
  <Tab title="macOS">
    The service is a launchd daemon called `ai.rubixkube.observer`. Logs go to `/etc/rk-observer/observer.log`.

    ```bash
    sudo launchctl print system/ai.rubixkube.observer
    sudo tail -f /etc/rk-observer/observer.log
    ```
  </Tab>
</Tabs>

## What the observer watches

Every 30 seconds it checks the machine and reports a problem when a value crosses a limit.

| Check | Default limit | Setting |
|---|---|---|
| CPU | 85% | `CPU_THRESHOLD` |
| Memory | 85% | `MEMORY_THRESHOLD` |
| Disk, per mount | 90% | `DISK_THRESHOLD` |
| Swap | 50% | `SWAP_THRESHOLD` |
| Load average | 2 × cores | `LOAD_AVG_THRESHOLD` (0 means 2 × cores) |
| Zombie processes | Fixed | |

It also sends a picture of the machine: processes, services, disks and network interfaces. You see these on the source's page.

## Change the settings

Settings live in `/etc/rk-observer/observer.env`. For example, to check every minute on Linux:

```bash
sudo sed -i 's/^SYSTEM_POLL_INTERVAL=.*/SYSTEM_POLL_INTERVAL=60s/' /etc/rk-observer/observer.env
sudo systemctl restart rk-observer
```

On macOS, edit the file and then run:

```bash
sudo launchctl kickstart -k system/ai.rubixkube.observer
```

The **Configuration** panel in the console doesn't apply to this observer.

## Many machines

Install on each machine. Each one is its own source, and you can put them all under one [environment label](/using/environments#label-a-source). The installer asks its questions in a terminal, so run it by hand on each machine.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The installer says it requires root">
    Run it again with `sudo`, as shown in [Install](#install).
  </Accordion>
  <Accordion title="The installer says systemd is required">
    On Linux the observer runs as a systemd service. A machine without systemd, such as Alpine, can't run this install.
  </Accordion>
  <Accordion title="The service won't start">
    ```bash
    sudo journalctl -u rk-observer -n 50
    ```

    Check the API key in `/etc/rk-observer/observer.env`. On macOS, read `/etc/rk-observer/observer.log`.
  </Accordion>
  <Accordion title="The source doesn't appear in the console">
    1. Check that the service is running.
    2. Check the connections:

    ```bash
    curl -I https://api.rubixkube.ai
    nc -zv nats.rubixkube.ai 4222
    ```
  </Accordion>
</AccordionGroup>

## Uninstall

Run the installer with `--uninstall`, so it doesn't ask for a key:

```bash
curl -fsSL "https://api.rubixkube.ai/install/observer.sh" | sudo bash -s -- --uninstall
```

Pick **1) This machine (local install)**, then **1) VM / AWS (binary + systemd)**. It stops the service and removes the binary and `/etc/rk-observer`. Then delete the source in the console.

To remove it by hand on Linux:

```bash
sudo systemctl stop rk-observer
sudo systemctl disable rk-observer
sudo rm -f /etc/systemd/system/rk-observer.service
sudo rm -rf /etc/rk-observer /usr/local/bin/rk-observer
sudo systemctl daemon-reload
```
