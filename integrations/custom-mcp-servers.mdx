---
title: "Custom MCP servers"
description: "Add your own MCP server so Rubix can use your internal tools."
---

MCP (Model Context Protocol) is the open standard Rubix uses to reach tools. Add your own server when you have an internal tool or data source that isn't in the [catalog](/integrations/catalog). Custom integrations are **Business and Enterprise**.

## Before you start

RubixKube calls your server from outside your network, so it needs a public `https` address. For a server that lives inside a Kubernetes cluster, [add it to the observer](/environments/kubernetes#add-your-own-mcp-servers) instead. That's available on every plan and needs no public address.

## Add the server

<Steps titleSize="h3">
  <Step title="Start adding it">
    Go to **Customize > Integrations**, choose **Add your own** and give it a name. Set **What it is** to **MCP server**.
  </Step>
  <Step title="Enter the address">
    Enter the server's address, such as `https://mcp.example.com/mcp`. RubixKube asks the server how it signs in and fills in what it finds. **Transport** is **Streamable HTTP** or **SSE**.
  </Step>
  <Step title="Set the sign-in">
    Choose **No sign-in**, **Token** or **OAuth**. A token is sent as a Bearer token and stored encrypted. See [Sign-in and tokens](/integrations/oauth-and-auth-types).
  </Step>
  <Step title="Add it and check it">
    Choose **Add**. For OAuth, sign in with the provider. Then choose **Check connection**.
  </Step>
</Steps>

Rubix finds the server's tools when it connects. The **Tools** list shows each one with a switch, and **Rubix can use it** turns the whole server on or off.

## What makes a good server

- **Clear descriptions.** Rubix reads each tool's description to decide when to use it. "Look up which customers are affected by an outage" beats "customer tool".
- **Narrow inputs.** Fixed choices and ranges work better than free text.
- **Label your reads.** Set `readOnlyHint` on tools that only read. During an RCA, Rubix only calls tools labelled as reads.
- **Useful errors.** Say what went wrong in words Rubix can act on.

Anything that changes something follows your [modes](/using/modes), so a custom server gets the same checks as every other tool.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The server is added but no tools appear">
    Rubix lists tools when it connects. Choose **Check connection**, then look at your server's log for errors in the MCP handshake.
  </Accordion>
  <Accordion title="The address is refused">
    It has to be a public `https` address. Private addresses and names such as `.internal` or `.local` aren't accepted.
  </Accordion>
  <Accordion title="Rubix doesn't use a tool during an RCA">
    Check that the tool is labelled as read-only. Without that label, it counts as a change.
  </Accordion>
</AccordionGroup>
