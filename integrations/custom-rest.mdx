---
title: "Custom REST APIs"
description: "Add a REST API so Rubix can call its endpoints as tools."
---

If your internal tool has a REST API, you can add it without writing an MCP server. Each endpoint you add becomes a tool Rubix can call. Custom integrations are **Business and Enterprise**.

## Add the API

<Steps titleSize="h3">
  <Step title="Start adding it">
    Go to **Customize > Integrations**, choose **Add your own** and give it a name. Set **What it is** to **REST API**.
  </Step>
  <Step title="Enter the address">
    Enter the base address, such as `https://api.example.com`. Endpoint paths are added to the end of it. It has to be a public `https` address.
  </Step>
  <Step title="Set the sign-in">
    Choose **No sign-in**, **Token**, **API key** or **Username and password**. See [Sign-in and tokens](/integrations/oauth-and-auth-types).
  </Step>
  <Step title="Add the endpoints">
    Import an OpenAPI or Swagger file by link, or paste or drop it in as JSON or YAML. Or add endpoints by hand with a method, path, tool name, description and inputs. Imported endpoints that make changes start off, so you turn on only the ones you want.
  </Step>
  <Step title="Add extra headers">
    Add any headers the API needs on every call. These aren't encrypted, so keep secrets in the sign-in.
  </Step>
  <Step title="Add it and check it">
    Choose **Add**, then **Check connection**.
  </Step>
</Steps>

## What makes a good API

- **Clear descriptions.** Rubix reads each endpoint's description to decide when to use it.
- **Start with reads.** Add `GET` endpoints first, and turn on changes once those work.
- **Narrow inputs.** Fixed choices and ranges work better than free text.
- **Pages, not floods.** Long lists should page, so one call doesn't return everything.

Anything that changes something follows your [modes](/using/modes). In Observe, Rubix can't call it. In Assist, it asks first.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The file won't import">
    The file has to be JSON or YAML with a `paths` section.
  </Accordion>
  <Accordion title="Calls fail with a sign-in error">
    **Token** is sent as `Authorization: Bearer <token>`, and **API key** as `Authorization: Token <key>`. Use the one your API expects.
  </Accordion>
  <Accordion title="Rubix calls the wrong endpoint">
    Sharpen the description of the one it should prefer. Rubix chooses from what the description says.
  </Accordion>
</AccordionGroup>
