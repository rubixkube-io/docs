---
title: "Grafana"
description: "Turn Grafana alerts into incidents, and let Rubix query Grafana Cloud while it investigates."
---

Connect Grafana so a firing alert opens an incident in RubixKube, and its resolved message resolves it. This works with any Grafana that can send to a webhook. If you use Grafana Cloud, Rubix can also read it while it investigates.

## When you'd use this

- **Your alert rules live in Grafana.** Keep them there, and get an investigation for each one that fires.
- **You run Prometheus.** A Grafana contact point is the simplest way to get those alerts into RubixKube.
- **You self-host Grafana.** Webhook alerts work with any Grafana, not only Grafana Cloud.

## Connect it

<Steps titleSize="h3">
  <Step title="Make its webhook in RubixKube">
    Go to **Environments > Connect** and pick **Grafana**. Give it a name, then choose **Make its webhook**. Copy the URL. It's shown once, and anyone who has it can post to it.
  </Step>
  <Step title="Add a contact point in Grafana">
    In Grafana, go to **Alerting > Contact points** and add a **Webhook** contact point. Paste the URL.
  </Step>
  <Step title="Send one alert per message">
    Under the webhook's optional settings, set **Max alerts per message** to 1. RubixKube reads only the first alert in a message, so a higher number hides the rest.
  </Step>
  <Step title="Route your alerts to it">
    Add the contact point to the notification policy for the alerts you want.
  </Step>
</Steps>

## What opens an incident and what resolves it

| Alert status | What happens |
|---|---|
| `firing` | Opens or updates the incident |
| `resolved` | Resolves the incident |

**Severity** comes from the alert's `severity` label: `critical` is critical, `high` or `error` is high, `warning` or `medium` is medium, `low` or `info` is low. With no label, it's medium.

Each alert's own Grafana fingerprint decides which incident it belongs to, so a firing alert that repeats updates the same incident.

## What you'll see

The source appears on **Environments** as soon as you make its webhook, then shows as connected when the first message arrives. Its page has an **Events** tab with the last 20 messages, so you can check what Grafana really sent.

The automation **Grafana alerts become incidents** is on under **Automations**. If events arrive and no incident opens, the source page says so and offers **Turn on**.

Each incident carries the alert's details and a link back to Grafana. Triage, the RCA and Tasks then work as they do for any other incident.

## What Rubix can read too

To let Rubix read Grafana Cloud, open **Customize > Integrations**, pick **Grafana Cloud** and sign in. RubixKube asks for read and query access, not write access.

For a Grafana you run yourself, add its MCP server to the observer. See [Add your own MCP servers](/environments/kubernetes#add-your-own-mcp-servers).
