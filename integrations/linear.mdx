---
title: "Linear"
description: "Turn the Linear issues your team labels incident into RubixKube incidents, and let Rubix read Linear."
---

Connect Linear so an issue labelled `incident` opens an incident in RubixKube, and completing or cancelling it resolves it. Other issues are left alone. You can also connect Linear as a tool Rubix reads while it investigates.

## When you'd use this

- **Your team tracks work in Linear.** Add the `incident` label to an issue, and Rubix starts looking.
- **You want Rubix to find related work.** With a connection, an RCA can read the issues around a problem.

## Connect it

<Steps titleSize="h3">
  <Step title="Make its webhook in RubixKube">
    Go to **Environments > Connect** and pick **Linear**. Give it a name, then choose **Make its webhook**. Copy the URL. It's shown once, and anyone who has it can post to it.
  </Step>
  <Step title="Add the webhook in Linear">
    In Linear, go to **Settings > API > Webhooks** and create a new webhook. Paste the URL.
  </Step>
  <Step title="Pick what it covers">
    Choose one team or all public teams, and tick the **Issues** resource type.
  </Step>
</Steps>

## What opens an incident and what resolves it

| Linear event | What happens |
|---|---|
| An issue labelled `incident` is created | Opens the incident |
| An issue labelled `incident` is updated | Opens or updates the incident, so adding the label to an existing issue opens one |
| An issue labelled `incident` moves to completed or canceled | Resolves the incident |
| An issue is removed | Resolves its incident, if it has one |
| Anything else | Ignored |

**Severity** comes from the issue's priority: Urgent is critical, High is high, Medium is medium, Low is low. With no priority, it's medium.

## What you'll see

The source appears on **Environments** as soon as you make its webhook, then shows as connected when the first message arrives. Its page has an **Events** tab with the last 20 messages, so you can check what Linear really sent.

The automation **Linear issues become incidents** is on under **Automations**. If events arrive and no incident opens, the source page says so and offers **Turn on**.

Each incident carries the alert's details and a link back to Linear. Triage, the RCA and Tasks then work as they do for any other incident.

## What Rubix can read too

To let Rubix read Linear while it investigates, open **Customize > Integrations**, pick **Linear**, and choose **Sign in with Linear** or paste an **API key**.

The connection's tools come from Linear's own server, and the **Tools** list shows each one. Anything that changes Linear follows your [modes](/using/modes).
