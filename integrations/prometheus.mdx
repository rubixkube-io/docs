---
title: "Prometheus"
description: "Let Rubix query Prometheus inside your cluster through the Kubernetes observer."
---

Prometheus usually runs inside your cluster with no public address, so it doesn't connect from **Customize > Integrations**. It reaches Rubix through the [Kubernetes observer](/environments/kubernetes) instead, which already runs next to it.

## Connect it

<Steps titleSize="h3">
  <Step title="Run a Prometheus MCP server">
    Run an MCP server for Prometheus in your cluster. RubixKube doesn't ship one, so use the one you prefer.
  </Step>
  <Step title="Add it to the observer">
    List it in the `mcp-config` ConfigMap in `rubixkube-system`, then restart the observer. [Add your own MCP servers](/environments/kubernetes#add-your-own-mcp-servers) has the exact commands.
  </Step>
  <Step title="Check it">
    Open the environment's page in the console. Each server shows as connected or failing, with the error.
  </Step>
</Steps>

## What Rubix can read

Rubix can use the tools your MCP server offers, usually PromQL queries and alert state. This also works for Thanos, Mimir, Loki and anything else with an MCP server in your cluster.

Alertmanager's webhook format isn't one RubixKube reads. To open incidents from Prometheus alerts, send them through a [Grafana](/integrations/grafana) contact point, or use a small script that posts to [your own webhook](/integrations/webhooks).
