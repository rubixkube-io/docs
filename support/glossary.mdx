The words RubixKube uses, in one plain sentence each.

| Word | What it means |
| --- | --- |
| **Agents** | Your own specialists, set up in Customize, that Rubix can hand work to. |
| **Assist** | The mode where Rubix can change things and asks a person before each change. |
| **Auto** | The mode where Rubix changes things without asking, and destructive changes always ask. |
| **Automations** | Steps that run on a trigger or a schedule, which you can build and whose runs you can see. |
| **Business** | The plan for teams, with higher limits and every feature. |
| **Channels** | The places your team talks to Rubix together, such as Slack. |
| **Commands** | Prompts your team uses often, saved as slash commands. |
| **Confidence** | How sure Rubix is of an RCA's cause. |
| **Customize** | The console area for what shapes Rubix: Integrations, Channels, Skills, Commands, Agents, Hooks and Webhooks. |
| **Enterprise** | The plan with limits and support set for your organization. |
| **Environment** | A label across sources, such as staging or production. |
| **Evidence** | The logs, events and tool results an RCA cites for its conclusions. |
| **Fix** | A Task that addresses the cause an RCA found. |
| **Follow-up** | A Task that stops the same problem from happening again. |
| **Group** | Incidents with the same resource or cause, shown together and sharing one RCA. |
| **Hooks** | Your own checks that run before Rubix changes something or reads a message. |
| **Incident** | Something that broke or got worse, reported by an observer, a tool or a person. |
| **Individual** | The free plan, with 1 environment, 10 investigations a month and 1 user. |
| **Integration** | A connection to a tool that Rubix can use. |
| **Investigation** | One RCA report, which is what your plan's monthly limit counts. |
| **Knowledge graph** | The map RubixKube keeps of your resources, incidents, RCAs and how they connect. |
| **Known** | An alert that earlier RCAs show is expected, so no RCA runs for it. |
| **MCP** | Model Context Protocol, the open standard that lets AI tools connect to RubixKube and lets Rubix connect to other tools. |
| **Member** | A person in your organization. |
| **Mode** | How much Rubix can do without asking: Observe, Assist or Auto. |
| **Needs you** | An incident that recovered and is waiting for someone to say what fixed it. |
| **Observe** | The mode where Rubix reads and investigates, and nothing that changes anything runs. |
| **Observer** | A small program you install next to your systems that watches them and reports back. |
| **Organization** | Your team's shared home in RubixKube, with its sources, incidents and members. |
| **RCA** | Root cause analysis, the report Rubix writes on what caused an incident. |
| **Recovered** | The observer saw the problem go away, whether or not the incident is closed yet. |
| **Rubix** | The agent you work with. |
| **RubixKube** | The product. |
| **Run RCA again** | Starts a new RCA now. It shows once an RCA has finished or failed, or when none is coming. |
| **Severity** | How serious an incident is: critical, high, medium or low. |
| **Skills** | Instructions Rubix loads when a task needs them. |
| **Source** | A Kubernetes cluster, cloud account, machine or tool that reports to RubixKube. |
| **Task** | A piece of work with an owner, either a Fix or a Follow-up. |
| **Triage** | The first look at a new incident, which can change its severity and impact, hold its RCA or mark it known. |
| **Verifying** | Rubix is checking that a recovery holds before it starts an RCA. |
| **Webhook** | A URL that a tool sends events to, or that RubixKube sends events from. |
