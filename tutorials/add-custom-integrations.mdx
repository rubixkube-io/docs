The [catalog](/integrations/catalog) covers the common tools. For everything else you run, you can add your own. This tutorial walks through both ways. You'll need to be an admin, on **Business or Enterprise**.

## Pick a way

- **Your tool has an MCP server already:** use it, and follow Path B.
- **Your tool has a REST API:** follow Path A. It needs no new code.
- **Neither, or the tool runs inside your Kubernetes cluster:** write an MCP server and [add it to the observer](/environments/kubernetes#add-your-own-mcp-servers). That works on every plan and needs no public address.

Either custom path needs a public `https` address.

## Path A: a REST API

<Steps titleSize="h3">
  <Step title="Find your OpenAPI file">
    Most internal tools have an OpenAPI or Swagger file, or can generate one. You can also add endpoints by hand.
  </Step>
  <Step title="Start adding it">
    Go to **Customize > Integrations** and choose **Add your own**. Name it, then set **What it is** to **REST API**.
  </Step>
  <Step title="Enter the address and sign-in">
    Enter the base address. Choose **No sign-in**, **Token**, **API key** or **Username and password**.
  </Step>
  <Step title="Import the endpoints">
    Import the file by link, or paste or drop it in. Each endpoint becomes a tool. Ones that make changes start off.
  </Step>
  <Step title="Add it and check it">
    Choose **Add**, then **Check connection**.
  </Step>
</Steps>

Every detail is on [Custom REST APIs](/integrations/custom-rest).

## Path B: an MCP server

<Steps titleSize="h3">
  <Step title="Write or adopt a server">
    MCP is an open protocol with official SDKs. Your server lists tools, each with a description and a schema for its inputs.
  </Step>
  <Step title="Host it">
    Run it on your own infrastructure with a public `https` address.
  </Step>
  <Step title="Add it">
    Go to **Customize > Integrations** and choose **Add your own**. Set **What it is** to **MCP server** and enter the address. RubixKube asks the server how it signs in.
  </Step>
  <Step title="Check it">
    Choose **Add**, sign in if needed, then **Check connection**. Rubix finds the server's tools when it connects, and the **Tools** list shows each one with a switch.
  </Step>
</Steps>

Every detail is on [Custom MCP servers](/integrations/custom-mcp-servers).

<Warning>
Any tool that changes something follows your [modes](/using/modes). In Auto, Rubix runs it without asking unless it's destructive. Start with reads, and turn on changes one at a time with the switches in the **Tools** list.
</Warning>

## Teach Rubix when to use it

Once the tools are there, a [skill](/tutorials/add-custom-agent-skills) can tell Rubix how your team uses them: which tool to try first, and what a good answer looks like.

## Common questions

<AccordionGroup>
  <Accordion title="Can I add a server that runs inside my cluster?">
    Yes, through the Kubernetes observer. See [Add your own MCP servers](/environments/kubernetes#add-your-own-mcp-servers).
  </Accordion>
  <Accordion title="How are secrets stored?">
    Sign-in details are stored encrypted. Extra headers aren't, so keep secrets in the sign-in.
  </Accordion>
</AccordionGroup>
