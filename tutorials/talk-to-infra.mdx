Ask Rubix what you'd ask a senior engineer. It reads your sources, past incidents and connected tools, then answers in plain English. You don't need `kubectl` commands or a query language.

Open a chat with **New session** in the sidebar, or click **Ask Rubix** on any page. Rubix remembers the session, so follow-ups don't start from scratch. Each step it takes shows in the chat, and you can open a step to see what it ran. The same questions work for Kubernetes, AWS, Google Cloud and machines.

## The difference, in two lines

The old way on Kubernetes:

```bash
kubectl get pods -n production
kubectl describe pod payments-api-xyz
kubectl logs payments-api-xyz
kubectl top pod payments-api-xyz
# five more commands, then stitch it together in your head
```

With Rubix:

```
Why is payments-api crash-looping?
```

You get one answer in one place.

## The four kinds of question that work

<AccordionGroup>
  <Accordion title="Health checks" icon="heart-pulse">
    Use for the daily read.

    ```
    How healthy are my environments?
    Which workloads are degraded right now?
    Any hosts above 80% memory in the last hour?
    ```
  </Accordion>
  <Accordion title="What changed" icon="timeline">
    Use when something broke.

    ```
    What changed in orders-api in the last hour?
    Which deployments rolled back in the last 24 hours?
    Show me configuration changes on prod-us-east-1 this week.
    ```
  </Accordion>
  <Accordion title="Investigation" icon="magnifying-glass">
    Use to dig into one thing.

    ```
    Why is payments-api slow in prod-us-east-1?
    Which pods restarted most in the last 24 hours, grouped by namespace?
    Top five CPU consumers on host-42 in the last hour.
    ```
  </Accordion>
  <Accordion title="Cost and capacity" icon="chart-line">
    Use for regular right-sizing.

    ```
    Which services have the most headroom on CPU limits?
    RDS instances with the lowest average utilization this month.
    GCE instances with far more memory than they use.
    ```
  </Accordion>
</AccordionGroup>

## Commands worth knowing

Type `/` in an empty message box, or click the `/` button.

| Command | What it does |
| --- | --- |
| `/new` | Starts a new session |
| `/model` | Picks the model Rubix answers with |
| `/mode` | Picks what Rubix can do in this session |
| `/env` | Picks the environment Rubix looks at |

`/settings`, `/customize` and `/shortcuts` open those pages from the same menu. Your organization's own commands from **Customize > Commands** show there too. To point Rubix at one incident, RCA or Task, type `@` and pick it.

## Quick reference

Five prompts that cover most days:

1. `What is failing?` for a morning check.
2. `Why is <service> slow?` to look into one service.
3. `What changed in <namespace> in the last hour?` after a deploy.
4. `Validate this`, with a YAML file attached, before a deploy.
5. `Explain <concept>` to learn something using your own resources as examples.

## Common questions

<AccordionGroup>
  <Accordion title="Does chat work across environments?">
    Yes. Ask broadly and Rubix looks at all of them. Use `/env` to pick one.
  </Accordion>
  <Accordion title="Can Rubix change my infrastructure from chat?">
    That depends on the session's mode. In Observe it only reads. In Assist it asks before each change. In Auto it changes things without asking, and destructive actions still ask. See [Modes](/using/modes).
  </Accordion>
  <Accordion title="Can I add files?">
    Yes. Attach screenshots, PDFs, logs, YAML, JSON and other text files to a message.
  </Accordion>
  <Accordion title="Is there a terminal version?">
    Yes. See the [Rubix CLI](/cli/overview).
  </Accordion>
</AccordionGroup>
